# Interview 文档导航

> 目标：通读一遍，对项目的每个技术点都能形成完整证据链（问题→方案→取舍→数据→失败→改进），面试时无论从哪个角度被问，都能有条理地讲出来。

## 阅读指南

| 时间 | 读什么 | 达成什么 |
|---|---|---|
| 3 分钟 | `01-overview.md` | 能说清项目是什么、为什么做、30 秒电梯陈述 |
| 30 分钟 | `02` + `03` | 能深入讲 2-3 个核心技术点 |
| 3 小时 | 全部 + `05-qa-bank.md` 模拟问答 | 任何角度被问都能答 |

## 文档地图

| 文件 | 内容 | 面试对应 |
|---|---|---|
| `01-overview.md` | 项目介绍 + 分工 + 电梯陈述 | "介绍一下你的项目" |
| `02-architecture.md` | 架构 + 技术栈选型 | "为什么用这个技术" |
| `03-core-techniques.md` | 核心技术点证据链 | "某个功能怎么实现的" |
| `04-ai-workflow.md` | AI 协作流程 + 验证方法 | "你怎么用 AI / 怎么验证 AI" |
| `05-qa-bank.md` | 面试问答库 | 模拟提问 |
| `06-self-check.md` | 自查清单 | 面试前最后过一遍 |

## 写作原则

1. 每个点独立成篇，单独被问也能答
2. 结论先行，再给过程
3. 有数字，不用模糊词
4. 只保留有决策价值的内容
